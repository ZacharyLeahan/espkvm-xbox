# C790 audio startup investigation, 2026-10-25

## Reproduced failure

Device 192.168.1.169 ran `v.0.56.1-160-g118eac1-dirty`, ota_0.
Before edits, GET `/audio.pcm` returned HTTP 503 and an 84-byte error body.
Audio status reported enabled/available, zero frames, zero overruns and
sample_age_ms=-1. These are absent samples, not measured silence.

The contemporaneous system log identifies the failure before any I2S read:
`i2s_alloc_dma_desc: allocate DMA buffer failed`, followed by failed slot and
channel initialization. Internal free memory was 23,559 bytes, largest block
8,960 bytes, with 16,861,304 bytes PSRAM free. Eight 240-frame stereo 32-bit DMA
buffers require 15,360 bytes, plus descriptors, queues and channel state.
Total heap/PSRAM availability does not establish internal DMA availability.
The generic 503 wiring/clock message obscured this allocation failure.

Bridge logs simultaneously reported sample=1, FS_CODE=2 (48 kHz),
CONFCTL=0x0c17, I2S_FMT=0x02, SYS=0x9f, FORCE=0, FS=22/00, ACR=01,
DIV=10. Video was 720x480 with about 300 completions per five seconds.
These register values do not establish physical I2S clock/data presence.
No settings, Xbox files or source playback were changed for reproduction.

## Revision comparison

The last documented non-silent source baseline is the 2026-10-16 validation:
bridge fix `ca27f5576918cc26196593782423d783509699e1`, API
`d6daefe0492e542ebdf2f9ca5939cb788520135a`, network
`59da2481b330042d9d4edabdff87ce407c852693`, and console
`03f0a719ae272c2fd5ed2ed60000c26db68fde50`. It was flashed before those
changes were committed, so there is no single exact clean working revision.
See AUDIO-VALIDATION-2026-10-16.md for WAV checksum and nonzero measurements.
Later 2026-10-17 capture checks in UPSTREAM-REVIEW.md include quiet sources;
they establish transport, not recognition of source sound. The particular
eight-second stereo capture cited in the request has not yet been matched
to an exact source revision. Do not label an arbitrary commit last-known-good.

`1e83a010cb1f92a19bf94a15b2e4cd4d978d4496` introduced shared browser/SD
capture. It and the earlier direct browser receiver both allocate the receiver
lazily after a disposable capability probe. Thus this lifecycle weakness
predates shared capture; no bisected regression introduction is established.
New runtime memory demand remains a hypothesis for why it now manifests.

From ca27f55 to 118eac1, the bridge audio register sequence and HDMI PLL
restoration are unchanged. Bridge changes bound I2C timeouts and abort failed
timing polls. The receiver remains Philips slave I2S, both stereo slots,
GPIO22 BCLK / GPIO53 WS / GPIO27 DIN, 48 kHz, 32-bit slots, high 16 bits
converted to s16le. There is no automatic sample-rate negotiation or physical
clock measurement. Each read waits 500 ms; source-clock timeout terminates
capture, and browser retry starts another session. Overrun recovery disables
and enables I2S and increments the capture epoch. Transport gaps and independent
subscriber queue drops are distinct from receiver overruns and quiet PCM.

## Candidate correction

`af7f29a` logs the terminal capture-read error, separately from delivery stats.
`eab6568` retains the receiver allocated by the boot capability probe and stops
DMA while idle, reusing that allocation for subsequent captures. It adds
internal/DMA heap diagnostics for receiver initialization failure. Reserving
these buffers costs internal memory even while audio is idle; this is an
opt-in audio build. IDF resets its RX message queue on channel enable; the
worker also resets timestamp state and advances epoch before each start.
No C790 format/clock/slot settings were changed.

The Xbox testing chat confirmed a safe KVM maintenance window, requesting that
the Xbox remain running and the game not be relaunched. Pre-maintenance logs
and status are preserved in ignored `observations/c790-audio-2026-10-25/`.

## Installed candidate and results

Both audio-enabled builds passed. No compiler warning/error lines appeared in
the incremental S3 build log. The flashed S3-profile image SHA-256 is
`06033ad72d6baa3e980690a395d1c597cab37f31c77ca65cfd82c7cb9a70e1af`.
Its compiled source includes af7f29a/eab6568 (both diagnostic strings were
checked in the image). CMake retained the earlier configure-time version
`v.0.56.1-162-g2f6bed5-dirty`; identify this candidate by its checksum, not
that stale embedded Git label. Unrelated roadmap edits remain uncommitted.

Installation used the inactive OTA slot, preserving ota_0 as the previous
image. The first attempt was refused by the explicit-write guard without
writing; adding its required header succeeded:

```sh
curl --max-time 60 -H 'Content-Type: application/octet-stream' \
  -H 'X-ESP-KVM: 1' --data-binary @build.s3-player1/espkvm.bin \
  http://192.168.1.169/api/v1/system/update
```

The unit rebooted into ota_1, serving the console with all four controller
indicators configured. At 21 seconds uptime it had 71,927 internal bytes free;
at 67 seconds, 54,055 bytes. Reboot also resets runtime memory pressure, so
these figures alone do not demonstrate the reservation fix or isolate which
feature consumed memory before the failure. No source restart was performed.

First WAV: 48 kHz, stereo, signed 16-bit samples. Independent channel analysis
found RMS 0.189496 left / 0.190254 right, mean -12.63/-10.07 counts, and
29/27 full-scale samples out of 381,840 samples per channel. Both channels
contain activity; source recognition and distortion assessment require
listening. A user listening check was requested with the saved eight-second
WAV. The user confirmed that this capture matches the Xbox's current Super
Mario War audio and sounds clear. This establishes recognizable source sound
for that eight-second artifact; it does not establish sustained delivery or
subjective browser output quality. Full-scale peaks alone do not prove a
slot-format error.

The startup allocation failure is addressed by retaining its DMA allocation;
the existing transport-timeout problem remains. Do not mark end-to-end audio
fixed. Source restart/video-mode recovery was deliberately not exercised in
this maintenance window, which required keeping the Xbox/game running.
The test viewer was restored after the isolated trial. The candidate remains
in ota_1; the previous firmware is preserved in ota_0. No changes were pushed.
